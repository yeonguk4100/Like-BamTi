## 1. 정체성 — 뿌리는 하나다

> **"성적·출결·스크린타임을 AI가 상시 분석해, 스스로 위기를 인지하지 못한 '전조 단계' 학생을 찾아 교내 상담센터로 연결하는 조기검진 시스템."**

- 카테고리: **AI 트래커** (챗봇 아님, 응원 앱 아님, 커뮤니티 아님)
- AI의 역할: **분석 엔진** — 신호를 읽고, 패턴을 감지하고, 우선순위를 매긴다. 학생과 대화하지 않는다
- 비유: 국가건강검진 — 평소엔 조용히 지표를 보다가, 이상 소견이 잡히면 검진(상담)으로 부른다

### 코어 루프 (이것이 서비스의 전부)

```
수집 (성적·출결·스크린타임)
  → 분석·감지 (AI: 2축 이상 동시 악화 = 전조 단계 판정)
    → 연계 (교내 상담센터 검진 배정)
```

이 세 단계 밖의 모든 것은 이 서비스가 아니다.

## 2. 대상

| 구분 | 정의 |
|---|---|
| **핵심 대상** | 위기 학생이 아닌 **그 전 단계** — 신호는 나빠지고 있지만 스스로 문제를 인지하지 못한 애매한 학생 |
| 사용 주체 | ① 대학 상담센터 (대시보드로 우선순위 큐 확인·배정) ② 학생 (검진 안내 수신, 스크린타임 옵트인 연동) |
| **명시적 제외** | 완전 위기 학생 (구제 어려움 — 상담센터가 전문기관으로 인계하는 출구까지만) / 반수·편입 등 목적 있는 이탈 준비자 / 입학 직후 조기이탈 (입학 전 배경이 결정 — 우리 사정권 밖) |

대표 사례 (페르소나 요약):
- **김서진(22)**: 학점 3.6→2.4, 결석 누적, 동아리 이탈 두 달. "상담센터 갈 정도는 아닌 것 같아서" 스스로는 아무것도 안 함 ← **본인이 안 움직여도 시스템이 감지하는 것**이 v2의 핵심
- **이하람(20, 신입생)**: 학사 데이터가 아직 없음 → 스크린타임 축이 첫 주부터 커버

## 3. 근거 (숫자 3개 + 논문 1개)

| 근거 | 내용 |
|---|---|
| 연 10만 명 | 4년제 대학 중도탈락자, 2년 연속 10만 명 초과 |
| 84.3% | 고립·은둔이 10~20대에 시작 — 대학 시기가 개입 골든타임 |
| 41.4% | 구직 포기 청년 중 정서적 고립 고위험군 (평균의 2.4배) |
| **JKDAS 2026 (고려대)** | 9년치 학사 데이터 분석 — 재학 중 이탈의 핵심 예측 변수는 **"성적 변동성과 비교과 활동 감소"라는 시계열 변화**. 우리 신호 설계의 학술적 기둥 |

수위 주의: "자퇴 = 고립"은 과장. 정확한 서사는 "활동 감소로 이어질 수 있고, 심해지면 자퇴일 수도 있다" + 그 끝에 니트·고립이라는 사회적 배경이 있다까지만. (상세: 연결고리 딥리서치)

## 4. 신호 기준표 (3축 확정)

| 신호 축 | 데이터 원천 | 해상도 | 위험 패턴 (감지 기준 초안) |
|---|---|---|---|
| 성적 | 학사시스템 (학교 제공) | 학기 단위 | 직전 학기 대비 하락폭, 성적 변동성 확대 [입증] |
| 출결 | 전자출결 (학교 제공) | 주 단위 | 특정 요일 연속 결석, 결석률 상승 추세 [입증] |
| **스크린타임** | **학생 옵트인 연동 / 주간 자가 입력** | **일 단위** | 새벽(0~6시) 사용 비중 상승, 주간 총량 급증, 사용 앱 다양성 감소 |

- **판정 규칙: 2개 축 이상 동시 악화 → 검진 우선 배정.** 단독 축은 오탐이 많다 (출결만 나쁜 창업·알바형, 스크린타임만 높은 게임 애호가를 걸러냄). "학업에 관심 없는 학생" 반박에 대한 답이기도 함
- 데이터 이원화 원칙: **학사 데이터는 학교가 제공, 민감한 생활 데이터(스크린타임)는 학생 본인이 선택 연동** — 프라이버시 설계의 핵심
- 스크린타임 수집 현실: 웹은 폰 기록 접근 불가, iOS API 제한 → MVP는 주간 자가 입력/스크린샷, 자동 수집은 안드로이드 네이티브 단계
- 스크린타임의 고유 가치: **신입생·복학생 콜드스타트 공백을 첫 주부터 메꾸는 유일한 축** (출결은 개강 2~3주 후, 성적은 학기말부터 작동)

## 5. 개입 설계 — 낙인 없는 "전수 검진 + 우선순위 배정"

- 감지된 학생만 호출하면 호출 자체가 낙인 → 방어적 상담으로 무효화
- 채택 프레임: **모든 학생이 학기 1회 15분 '적응 검진'을 받는 것을 기본**(신체검사와 같은 학칙 프레임)으로 하고, AI 트래커는 **누구를 먼저·자주 배정할지의 우선순위만** 결정
- 슬로건: **"국가건강검진처럼, 대학생활에도 정기 검진을."**

### ⏳ 미정 — 해결방안 상세 (고민 중, 결정 시 갱신)

| 결정 포인트 | 선택지 |
|---|---|
| 감지 후 첫 통보 대상 | 학생 본인 먼저(자기결정권) vs 상담센터 직접(확실성) vs 동시 |
| 연계 강제 수위 | 전수 검진+우선순위(낙인 없음, 제도 필요) vs 감지자만 의무 호출(간단, 낙인) vs 인센티브형 권유(마일리지 등) |
| 상담 이후 루프 | 일회성 연계 vs **재감지 루프**(상담 후에도 신호 악화 시 재배정 + 상담사에게 추이 리포트 — "검진→처방→경과 관찰" 완결 구조, 차별화 관점에서 유력) |

## 6. 사업 형태와 차별점

- **형태: B2B — 대학 도입형 시스템.** 고객은 대학(상담센터·학생처), 최종 수혜자는 학생
- 지불 근거: 학령인구 감소로 재학생 유지가 대학의 생존 과제. 대학들은 이미 AI 이탈예측 시스템에 지출 중 (스타트업엔·한국대학신문·유스라인 보도 — 해결서비스 딥리서치 참고)
- **차별점: "예측 시스템"이 아니라 "검진 시스템".** 기존 대학 AI 시스템은 중도탈락률(경영지표)을 예측해 관리자에게 보여주고 끝난다. 우리는 **예측 이후의 개입 구간**(검진 배정 → 상담 연계 → 경과 관찰)을 설계한다. 예측은 이미 다들 하고, 예측 후 개입 설계가 비어 있다

## 7. 해커톤 데모 전략

- 실제 학사 데이터 접근 불가 → **가상 학생 데이터셋**(예: 500명, 정상/전조/위기 분포)으로 구동
- 데모 화면 2개:
  1. **상담센터용 대시보드** — 우선순위 배정 큐, 3축 신호 히트맵, 학생별 추이 그래프
  2. **학생용 화면** — 검진 안내 수신, 스크린타임 연동(자가 입력)
- "실데이터 연동은 대학 제휴 단계"임을 발표에서 명시 — 숨기지 않는 것이 신뢰를 얻는다
- 4주 검증 지표: 데모 시나리오에서 전조 단계 학생이 감지→배정되는 전체 플로우 시연 + 판정 규칙의 오탐 케이스(창업형 학생) 구분 시연

## 8. 예상 질문 Q&A (v2 기준)

| 질문 | 답 |
|---|---|
| 챗봇인가요? | 아니다. AI는 학생과 대화하지 않는다. 신호를 분석해 전조 단계를 감지하는 엔진이다. |
| 기존 대학 AI 예측 시스템과 뭐가 다른가? | 그들은 예측해서 보여주고 끝. 우리는 예측 이후(검진 배정→상담 연계→경과 관찰)를 설계한다. |
| 학생 동의 없이 데이터를 분석해도 되나? | 입학 시 포괄 동의 체계 + 스크린타임은 별도 옵트인. 상담센터 외 제3자 제공 금지 하드 룰. |
| 감시 아닌가? | 데이터가 가는 곳은 성적처리 부서도 교수도 아닌 상담센터뿐이며, 결과는 "검진 배정"이라는 돌봄 행위 하나다. 전수 검진 프레임이라 호출 자체도 낙인이 아니다. |
| 그냥 학업에 관심 없는 학생이면? | 2축 이상 동시 악화 판정으로 구분 — 창업·알바형은 출결만 나쁘고 스크린타임·성적 패턴이 다르다. |
| 신입생·복학생은 데이터가 없잖아? | 스크린타임 축이 첫 주부터 커버. 학사 축은 2~3주 후 합류. 입학 직후 조기이탈은 사정권 밖임을 명시한다. |
| 완전 위기 학생은? | 구제 대상에서 제외를 명시한다. 상담센터가 전문기관(청년미래센터 등)으로 인계하는 출구까지만 설계. 우리는 "구제"가 아니라 "구제가 필요해지기 전 단계"를 맡는다. |
