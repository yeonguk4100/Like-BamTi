# 복지그루

**멋쟁이사자처럼 Campus AX-Ton 강원대 · 팀 프로젝트**
팀명: **멋쟁이 밤티들**

> 기관 담당자가 학부모 문의를 받았을 때 아동 조건을 넣으면, **어디에 · 무엇을 들고 · 언제까지**
> 가야 하는지를 한 장으로 정리해 **학부모에게 그대로 건넬 수 있게** 만드는 업무 도구.

**학부모가 한 번에 갖춰 오게 만들어 담당자의 반송과 재문의를 줄입니다** · 과제 트랙: 업무 효율화

이름은 「복지」와 나무 한 그루의 「그루」를 붙인 것입니다. 부처마다 갈라져 있는 지원제도를
한 그루로 모아 담당자와 학부모가 **같은 한 장**을 본다는 뜻입니다.

## 무엇이 문제인가

아이에게 장애가 있다는 것을 막 알게 된 부모는 무엇부터 해야 하는지 모릅니다. 그래서 기관에 전화합니다.
그런데 전화를 받은 담당자도 전부를, 그리고 지금 기준으로는 알기 어렵습니다.

세 겹으로 갈라져 있기 때문입니다.

| 무엇이 갈라져 있나 | 근거 |
|---|---|
| **부처가 갈려 있다** — 교육·복지·의료·고용 | 소관 부처별 신청처 상이 |
| **같은 교육청 안에서도 담당자가 갈려 있다** | 강원도교육청 지침 원문 |
| **제도 이름이 지역마다 다르고, 시간이 지나면 또 바뀐다** | 6개 시도 카드 명칭 대조 |

### 확인한 사실 두 가지

**① 같은 지원인데 시도마다 이름이 다릅니다**

| 시도 | 서울 | 경기 | 인천 | 강원 | 충남 | 경남 |
|---|---|---|---|---|---|---|
| 카드명 | 굳센카드 | 꿈이든카드 | 참좋은카드 | 마음모아카드 | 디딤카드 | 특기적성비지원카드 |

**② 폐지된 용어가 공식 지침에 남아 있습니다**

2019년 7월 장애등급제가 폐지되어 「장애등급」이 「장애정도」로 바뀌었습니다. 그런데 2025년 지침에서
**강원은 1회**(전환 안내 목적), **경남은 14회**(제출 서류로 반복 명시) 「장애등급」을 쓰고 있습니다.

경남 지침대로 안내하면 보호자에게 *"장애등급 결정서를 가져오세요"*라고 말하게 되는데,
**2019년 7월 이후 등록한 보호자에게는 그런 서류가 없습니다.**

## 사업 구조 — B2G2C

| | 누구 | 성격 |
|---|---|---|
| **구매자** | 시도교육청 / 교육지원청 | **B2G** |
| **사용자** | 기관 담당자 | **B2G** |
| **수혜자** | 학부모 (무료) | 2C |

교육청 조직은 위탁이 아니라 **직할**입니다. 특수교육지원센터는 법인격이 없고 교육지원청 안에 설치된
조직이라(특수교육법 제11조), **1개 시도교육청이 도입하면 산하 교육지원청 전부가 사용자가 됩니다.**
강원은 17개입니다.

## 설계 원칙

1. **판정하지 않는다** — "확인하세요"까지만. 최종 판단은 담당자
2. **개인정보를 저장하지 않는다** — 이름·연락처를 받지 않고, 입력값을 기록하지 않음
3. **근거를 반드시 붙인다** — 모든 항목에 법령·지침 출처
4. **담당자 업무를 늘리지 않는다** — 상담 중 어차피 묻는 것만 입력, 결과는 즉시 출력
5. **옛 이름도 함께 보여준다** — 담당자가 지침과 대조할 수 있도록

## 데모

```bash
npm install
```

```bash
npm run dev
```

http://localhost:3000

**데모의 두 장면**

1. 조건을 입력하면 **담당자용 확인 시트**와 **학부모용 안내문**이 동시에 나온다
2. 지역만 바꾸면 **카드 이름이 바뀌고**, 경남을 고르면 **⚠ 「장애등급 결정서」 경고**가 뜬다

> **데모 데이터 안내** — 절차·기한(30일/2주)·카드 명칭·장애영역별 검사도구는 강원·경남 교육청 지침
> 원문에서 확인한 내용입니다. 그 밖의 금액·세부 절차는 화면 구성을 보여주기 위한 **예시**이며,
> 화면에 `예시` 표시가 붙습니다. **입력하는 아동 정보는 전부 가상입니다.**

## 기술 구성

Next.js 15 (App Router) · React 19 · TypeScript. **새 npm 의존성 없음** (SDK 대신 `fetch`, 검증도 손으로)

| 층 | 파일 | 하는 일 |
|---|---|---|
| 데이터 | `app/lib/data.ts` | 지역 · 장애영역 · 학교급 · 신청 상황 · 서식 · 제도 |
| 규칙 | `app/lib/build-sheet.ts` | 조건 → 제도·마감일·서류·경고·안내문. 순수 함수 |
| 검증 | `app/lib/validate.ts` | 요청 본문 검사. 모르는 id는 통과시키지 않는다 |
| 게시판 | `app/lib/board.ts` | 알림 마당 · 서식 자료실 · FAQ 데이터 |
| 화면 | `app/page.tsx` · `app/globals.css` | 규칙 모듈을 브라우저에서 직접 부른다 |

### 백엔드

| 라우트 | 하는 일 | AI |
|---|---|---|
| `POST /api/sheet` | 조건 → 확인 시트 한 벌. **교육청 시스템이 붙는 자리** | ❌ |
| `GET /api/options` | 넣을 수 있는 id 목록 | ❌ |
| `GET /api/reference` | 지역별 카드 명칭 · 서식 번호 대조표 | ❌ |
| `GET /api/notices` | 알림 마당 · 서식 자료실 · FAQ | ❌ |
| `GET /api/health` | 배포 확인. 키 값은 응답에 넣지 않는다 | ❌ |
| `POST /api/letter` | 학부모용 안내문 문장화 | ⭕ 검색 끔 |
| `POST /api/lookup` | 우리 데이터에 없는 칸을 웹에서 찾기 | ⭕ Google Search |

**규칙이 고르고 AI가 쓴다.** 제도를 고르는 것은 규칙이다. 같은 조건에 같은 결과가 나와야
담당자가 신뢰할 수 있기 때문이다. AI는 규칙이 못 하는 두 가지만 한다 —
우리 데이터에 없는 칸을 웹에서 찾는 것, 그리고 학부모가 읽을 문장으로 옮기는 것.

화면과 API가 **같은 규칙 모듈**을 쓴다. 그래서 화면에 뜬 시트와 `/api/sheet` 응답이 어긋날 수 없다.
`/api/letter`는 조건만 받아 서버에서 규칙을 다시 돌리고 그 결과만 제미나이에 넘긴다 —
화면을 우회해 아무 내용이나 안내문에 밀어 넣을 수 없다. 생년월일과 담당자 연락처는 AI에 넘기지 않는다.

자세한 명세는 [docs/백엔드-API.md](docs/백엔드-API.md).

### 환경변수

| 이름 | 용도 |
|---|---|
| `GEMINI_API_KEY` | 없으면 AI 버튼만 안내 메시지를 낸다 |
| `GEMINI_MODEL` | 선택. 기본값 `gemini-3-flash-preview` |

`.env.example`을 `.env.local`로 복사해 채웁니다.
**키가 없어도 화면과 규칙 계산은 그대로 동작합니다.**

## Vercel 배포

1. [vercel.com/new](https://vercel.com/new) → 이 저장소(`yeonguk4100/Like-BamTi`)를 가져온다
2. Framework Preset이 **Next.js**로 잡히는지 확인한다. 빌드 명령·출력 경로는 그대로 둔다
3. **Environment Variables**에 `GEMINI_API_KEY`를 넣는다 (`GEMINI_MODEL`은 생략 가능).
   Production · Preview · Development 세 곳에 모두 넣어야 미리보기 배포에서도 AI가 돈다
4. Deploy

설정 파일(`vercel.json`)은 두지 않습니다. Next.js 프로젝트는 Vercel이 그대로 알아봅니다.

배포된 뒤 `/api/health`를 열어 확인합니다.

```
{ "ok": true, "ai": { "configured": true } }
```

`configured`가 `false`면 환경변수가 안 들어간 것입니다. 넣은 뒤 **다시 배포**해야 반영됩니다.

올리기 전에 로컬에서 확인:

```bash
npm run typecheck
```

```bash
npm run build
```
